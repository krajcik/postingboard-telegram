# Posting Board → Telegram

Telegram-интерфейс для чтения обеих досок [Posting Board](https://getpostingboard.dev/): основной доски агентов `/v1` и анонимной `/b`. Каждое обсуждение становится отдельной темой в группе, а исходный пост и ответы — сообщениями внутри неё. У `/b` нет заголовков: название темы берётся из первой непустой строки корневого сообщения и помечается `[/b]`.

Бот переносит всю доступную историю при первом запуске, затем проверяет новые записи раз в минуту. Состояние сохраняется в SQLite: обычные перезапуски и повторное чтение событий не создают дубли. Длинные тексты разбиваются на сообщения, автор и раздел сохраняются. Текст публикуется без интерпретации HTML/Markdown и без предпросмотра ссылок.

## Требования

- Python 3.10+ на Linux или macOS. Внешних Python-зависимостей нет.
- API-ключ для основной доски Posting Board. Его можно получить через открытую регистрацию без почты и пароля — см. [официальную инструкцию](https://getpostingboard.dev/skill.md). Для анонимной `/b` ключ не нужен.
- Telegram-бот, созданный через [@BotFather](https://t.me/BotFather).
- Супергруппа Telegram с включёнными темами. Бот должен быть администратором с правом управления темами и возможностью отправлять сообщения.

## Запуск

Из каталога репозитория:

```bash
cp .env.example .env
chmod 600 .env
```

Заполните `.env` локально:

```dotenv
POSTINGBOARD_API_KEY=ваш_ключ
TELEGRAM_BOT_TOKEN=ваш_токен
TELEGRAM_CHAT_ID=-1001234567890
```

ID группы можно получить из поля `message.chat.id` в `getUpdates` после сообщения в группе. Это числовой ID, а не название группы или ID темы. Получение обновлений и ограничения webhook описаны в [Telegram Bot API](https://core.telegram.org/bots/api#getupdates).

Проверьте доступ без отправки сообщений:

```bash
python3 bot.py check
```

Запустите синхронизацию:

```bash
python3 bot.py run
```

`run` сразу создаёт темы и публикует всю доступную историю обеих досок в указанную группу. События двух досок чередуются; между запросами, изменяющими Telegram, выдерживается общий интервал не менее 3,1 секунды. Для одного прохода используйте `python3 bot.py once`. Остановка — `Ctrl+C`.

Для отдельной доски: `python3 bot.py --board named run` или `python3 bot.py --board b run`. Режим `/b` не требует `POSTINGBOARD_API_KEY`.

Боту не требуется публичный HTTP-сервер, webhook или входящий порт. Для постоянной работы оставьте процесс запущенным на своём сервере под менеджером процессов. Рабочий каталог должен оставаться каталогом репозитория; при переносе сохраните `.state/`.

## Настройки

Переменные окружения имеют приоритет над `.env`. Другой файл можно выбрать через `python3 bot.py --env-file /path/to/.env run`. Файл читается как пары `KEY=value`, без shell-подстановок и выполнения команд.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `POSTINGBOARD_API_KEY` | обязательно | Bearer-ключ источника |
| `TELEGRAM_BOT_TOKEN` | обязательно | Токен Telegram-бота |
| `TELEGRAM_CHAT_ID` | обязательно | Числовой ID супергруппы |
| `POSTINGBOARD_BASE_URL` | `https://getpostingboard.dev` | HTTPS-адрес источника |
| `POLL_INTERVAL_SECONDS` | `60` | Пауза после цикла, минимум 60 секунд |
| `TELEGRAM_INTERVAL_SECONDS` | `3.1` | Интервал между изменениями Telegram, минимум 3,1 секунды |
| `STATE_PATH` | `.state/mirror.sqlite3` | Путь к состоянию, относительно рабочего каталога |
| `ANONYMOUS_STATE_PATH` | `.state/mirror.b.sqlite3` | Отдельная БД для `/b`; при изменении `STATE_PATH` по умолчанию добавляется `.b` перед расширением |
| `TELEGRAM_PROXY_URL` | пусто | HTTP(S)-прокси для Telegram, например `http://127.0.0.1:12334`; запросы Posting Board идут напрямую |

У досок раздельные БД, cursors и сопоставления Telegram ID. Каждая БД привязана к одной доске, группе и Telegram-боту. Для другой группы используйте отдельные пути состояния. Одновременный запуск двух процессов с одной БД блокируется. Не запускайте два независимых экземпляра с разными БД для одной доски в одну группу: их дедупликация не общая.

## Если результат отправки неизвестен

У Telegram нет клиентского ключа идемпотентности для создания тем и отправки сообщений. При обрыве связи сервер мог выполнить запрос, даже если бот не получил ответ. Поэтому перед каждым изменением бот сохраняет операцию в SQLite. При неопределённом результате он останавливается; слепого повтора нет.

Посмотрите незавершённую операцию:

```bash
python3 bot.py pending
```

Проверьте последнюю тему/сообщение в Telegram. Если операция выполнена, сохраните полученный ID:

```bash
# Для createForumTopic укажите message_thread_id, для sendMessage — message_id.
python3 bot.py --board named resolve 'ключ_из_pending' --telegram-id 123
python3 bot.py run
```

Если проверка показала, что тема/сообщение не появились, разрешите повтор:

```bash
python3 bot.py --board named resolve 'ключ_из_pending' --retry
python3 bot.py run
```

`pending` выводит операции отдельно для `named` и `b`. Для восстановления анонимной доски замените `--board named` на `--board b`. `--retry` может создать дубль, если предыдущая отправка всё-таки состоялась. ID темы/сообщения можно узнать из ссылки, скопированной в Telegram, или из соответствующего Telegram API update. Обе команды восстановления работают локально, без вызовов API.

При явном отказе `429` бот учитывает `retry_after`/`Retry-After` и повторяет после паузы. Ошибки прав/авторизации останавливают процесс. Ответы Telegram `5xx`, некорректные успешные ответы и обрывы сети считаются неопределённым результатом и требуют проверки.

## Границы версии

- Синхронизация односторонняя: Posting Board → Telegram. Сообщения людей в Telegram остаются в Telegram; команды боту и отправка ответов на доску пока не реализованы.
- Переносится весь текст доступных постов и ответов. Файлы по ссылкам не скачиваются; отдельного переноса вложений нет.
- Удаления не зеркалируются: в документированном API нет журнала удалений. Telegram-копия остаётся после удаления оригинала. API редактирования постов не документирован; бот не изменяет уже опубликованные сообщения.
- Удалённые вручную темы/сообщения Telegram автоматически не восстанавливаются. Откройте закрытую тему или восстановите назначение вручную перед продолжением.
- Состояние содержит копии опубликованных текстов. `.env`, `.state/` и SQLite исключены из Git; БД создаётся с правами `600`. Сохраняйте БД для продолжения работы без повторной публикации истории.
- Полный обход истории обеих досок и чтение полных текстов проверены на живом API. Доставка в Telegram требует проверки в вашей группе. Автотесты используют имитации ответов API, без живых учётных записей.

## Как работает синхронизация

1. `GET /v1/activity?after=cursor&limit=30` получает новые события. При первом запуске `after` отсутствует.
2. Лента идёт от новых событий к старым. Бот дочитывает окно через `before=next_before`, локально отсекая старые `seq`; `after` и `before` не отправляются вместе.
3. Только после успешного чтения всего окна события обрабатываются в порядке увеличения `seq`.
4. Для каждого события `GET /v1/posts/{id}` получает полный `body`; `preview` не используется как текст сообщения. Для ответа определяется корневой `thread_id`.
5. `createForumTopic` создаёт тему для корня, `sendMessage` отправляет части текста в её `message_thread_id`.
6. ID каждой успешной операции сохраняется немедленно. Cursor продвигается только после полной доставки события.

Анонимная доска читается через `GET /b` с `Accept: application/json`. Эта лента уже содержит полные тексты корней и ответов; из фильтров допускается только `before`. Бот дочитывает страницы до сохранённого cursor. Если корень нового ответа старше прочитанного окна, он запрашивается через `GET /b/t/{root_id}`. Ключ основной доски в `/b` не отправляется.

Проверенные публичные контракты: [Posting Board skill.md](https://getpostingboard.dev/skill.md), [OpenAPI](https://getpostingboard.dev/openapi.json), [руководство /b](https://getpostingboard.dev/b/guide), [Telegram Bot API](https://core.telegram.org/bots/api), [лимиты Telegram](https://core.telegram.org/bots/faq#my-bot-is-hitting-limits-how-do-i-avoid-this). Обход окна через `before` проверен на живой истории обеих досок. HTTP-клиент использует собственный User-Agent `postingboard-telegram/0.1`: стандартный `Python-urllib` отклоняется на стороне сайта.

## Проверка разработки

```bash
python3 -m unittest discover -s tests -v
python3 bot.py --help
```

Тесты проверяют перенос нескольких обсуждений, ответы в нужных темах, историю больше страницы, поступление новых событий во время обхода, возобновление после частичной отправки, Unicode, блокировку второго процесса, лимиты и восстановление неопределённых операций. Сеть и реальные ключи не используются.
